# プロダクト要求定義書

## プロダクトビジョンと目的

フリーランスエンジニア・小門真愛のポートフォリオサイト。開発実績・スキル・稼働可能状況を簡潔に伝えることで、潜在的なクライアントや協業パートナーとの接点を生む。

## ターゲットユーザーと課題・ニーズ

| ターゲット | 課題 | ニーズ |
|---|---|---|
| 案件発注者（企業・個人） | エンジニアのスキルセットや実績を短時間で把握したい | 実績・技術スタック・連絡先が一目でわかるサイト |
| 協業相手・エージェント | 稼働可能かどうかをすぐに確認したい | 稼働状況（Availability）がリアルタイムで見られること |

## 主要な機能一覧

| 機能 | 概要 |
|---|---|
| TOP | キャッチコピーとサイト概要の表示 |
| About | サイト・エンジニア本人の紹介文 |
| Works | 制作物のカルーセル表示（画像・タイトル・説明・タグ・リンク） |
| Profile | 氏名・役割・自己紹介・趣味 |
| Skills | カテゴリ別スキル一覧 |
| Contact | GitHub・X・メールへの外部リンク |
| Availability | 現在の稼働可能状況と受注開始可能時期 |

## 成功の定義

- 訪問者がエンジニアのスキル・実績・連絡先を1スクロール以内で把握できる
- Availability セクションを更新するだけで稼働状況を即時反映できる
- Google Lighthouse スコアで Performance・Accessibility・SEO がそれぞれ 90 以上

## ビジネス要件

- デプロイコスト：Vercel を使用し、Hobby プランでホスティングコスト 0 円
- 更新工数：コンテンツ変更は `data/*.json` の編集のみで完結
- ダウンタイム：静的サイトのため実質ゼロ

## ユーザーストーリー

1. 案件発注者として、エンジニアの技術スタックをすぐ確認したい。そうすれば依頼の可否を素早く判断できる。
2. 案件発注者として、現在受注可能かどうかを確認したい。そうすればコンタクトのタイミングを見計らえる。
3. エンジニア本人として、コンテンツをコードを書かずに更新したい。そうすれば手間をかけずに最新情報を公開できる。

## 受け入れ条件

- 全セクションがスマートフォン（320px〜）からデスクトップ（1280px）まで崩れずに表示される
- Works カルーセルがスワイプ・矢印ナビゲーションで操作できる
- Contact の各リンクが新しいタブで開く
- Availability の `status` / `from` / `message` を JSON で変更すると画面に即時反映される
- `npm run build` でビルドエラーが発生しない

## 機能要件

### Works セクション
- 制作物は `data/works.json` で管理
- 1件につき：タイトル・説明・サムネイル画像・タグ・URL（任意）・GitHub リンク（任意）・期間（任意）
- カルーセルは横スライド、ドラッグ/スワイプ対応

### Skills セクション
- スキルは `data/skills.json` でカテゴリ別に管理
- カテゴリ：フロントエンド / バックエンド / データベース / インフラ・クラウド / ツール・その他

### Availability セクション
- ステータスは `available` / `limited` / `unavailable` の3値
- 受注開始可能時期（`from`）と表示メッセージ（`message`）を JSON で制御

## 非機能要件

| 区分 | 要件 |
|---|---|
| パフォーマンス | Lighthouse Performance 90 以上 |
| アクセシビリティ | Lighthouse Accessibility 90 以上、WCAG AA 準拠（コントラスト比 4.5:1 以上） |
| SEO | Lighthouse SEO 90 以上、OGP / Twitter Card 設定済み |
| レスポンシブ | 320px〜1280px で表示崩れなし |
| ブラウザ対応 | Chrome / Safari / Firefox 最新版 |
| セキュリティ | XSS 対策（React のエスケープ機構に準拠）、外部リンクに `rel="noopener noreferrer"` 付与 |
| 保守性 | コンテンツ更新は `data/*.json` のみ、コード変更不要 |
